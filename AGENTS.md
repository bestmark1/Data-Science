# Вход для агента

Короткая карта. Правила не пересказываются здесь второй раз — они лежат в
`CLAUDE.md`, и это единственное место общего обязательного минимума. Отсюда
только указатели.

## Что это

**Переносимый инструментарий дата-сайентиста** (`src/dsx`): набор проверок,
который должен пережить смену отрасли. Подставили данные новой предметной
области — система продолжает работать и продолжает возражать по делу.

Проверяется он **кейсами**: прогон на настоящих данных под пре-регистрацией,
опечатанной до контакта с данными. Двадцать отраслей пройдено.

## С чего начать

1. **`docs/handoff.md`** — где остановились, что следующим шагом, чего не
   трогать, какие решения уже отвергнуты. Один экран.
2. **`CLAUDE.md`** — обязательный минимум: три правила ведения задачи и карта
   методологии.
3. **`docs/recurrence-ledger.md`** — на чём проект обжигался. Начинать с
   индекса в начале файла, а не читать целиком.
4. **[Режимы работы](CLAUDE.md#режимы-работы)** — Desktop и оркестратор
   Herdr, используемые по очереди; назначения ролей и порядок передачи.
5. **[docs/backlog.md](docs/backlog.md)** — единая очередь задач, статусы,
   назначенные роли и критерии приёмки.

## Команда проверок

```bash
.venv/bin/python tools/check.py
```

Тесты и стиль разом, ненулевой код возврата при провале, отдельный счёт
ненаступивших обещаний. Кейсы, сбор данных, мутацию порогов и слепой контроль
она НЕ запускает — это отдельные инструменты, и два из них правят файлы.

Окружение собирается `uv sync --extra dev`.

## Защищённое: не трогать без явного поручения

| Что | Почему |
|---|---|
| `docs/prereg-case-*.md` | опечатаны до данных; задним числом не переписываются даже при ошибке автора |
| `docs/case*-verdict.md` | вердикт закрыт; поправки дописываются дополнением, а не правкой |
| пороги в `src/dsx`, увиденные в действии | их правка под результат — подбор; ошибку записать, число оставить |
| `projects/*/data/` | не в git, 5+ ГБ, восстановимы через `acquire.py` лишь с оговоркой: источники живые |
| `projects/*/blind-control.*` | материалы слепого контроля; читать до записи заключения нельзя |
| `protocol/preflight.py` | порядок кейса; смягчать проверки ради прохождения запрещено |

## Порядок кейса — обеспечен кодом, а не памятью

С двадцать первого кейса `protocol.preflight` отказывает **до вызова
построителя**, если пропущен обязательный шаг. Обход остаётся возможным для
того, кто вызовет построитель напрямую: защищён штатный путь, не больше.

Подробности порядка и состояний — `docs/plans/2026-09-08-protocol-preflight-spec.md`.

## Где что лежит

| Путь | Что |
|---|---|
| `src/dsx/` | ядро: роли, контракт исхода, проверки, измерение, стенд |
| `protocol/` | порядок ведения кейса — вне ядра намеренно |
| `tools/` | измерители и пробы; `check.py` — команда проверок |
| `projects/<кейс>/` | сбор, построитель, формуляр, модель одного кейса |
| `examples/` | прикладной пример без внешних данных: форма → проверки → отчёт → измерение |
| `docs/` | пре-регистрации, вердикты, журнал повторов, учёты, handoff |
| `CONTEXT.md` | глоссарий: канонические термины и слова, которых избегать |

## Чего в этом проекте делать нельзя

Предлагать заново уже отвергнутое — список в конце `docs/handoff.md`, раздел
«Отвергнутое». Там записано, почему отклонены общий детектор недостижимого
кода, внешний трекинг экспериментов, генерация handoff программой и другое.
