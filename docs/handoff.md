# Где мы сейчас

Вход для модели, которая берётся за проект и не читала переписки. Один экран,
дальше — по указателям. Учёты ведут другие файлы: правило остановки —
`stopping-rule.md`, ошибки автора — `author-errors.md`, классы дефектов —
`recurrence-ledger.md`. Здесь их нет, здесь ссылки на них.

## Состояние

**Кейсов проведено: 19.** Последний — надзор за страховым рынком Техаса
(`projects/tx-insurance-complaints`), приёмку **не прошёл**: два предсказания
провалены слепотой проверки N14, разбор в `case19-verdict.md`.

**Стенд:** 74 кейса, 36 требований из 36 покрыто, 19 отрицательных контролей.

**Отсчёт правила остановки: не начат.** Обнулён семнадцатым кейсом, 18-й и 19-й
его не начали.

**Следующий шаг:** перемерить мутацию порогов. Прежний результат «47 из 50
прибиты» получен измерителем, который не запускал проверки по мирам стенда, —
эта слепота найдена в 19-м кейсе и закрыта тестом
`test_every_case_makes_the_core_answer_as_the_case_says`. До перемера числу
94% верить нельзя.

**Чего не трогать:**

* опечатанные пре-регистрации `docs/prereg-case-N.md` — задним числом не
  переписываются никогда, даже когда автор ошибся;
* пороги, увиденные в действии: ошибку записать, число оставить;
* данные кейсов в `projects/*/data` — 5.2 ГБ, не в git. Восстановимы через
  `acquire.py`, но **не гарантированно**: источники живые, объёмы меняются,
  и `acquire.py` откажет при расхождении с объявленным числом строк.

## Как этот файл поддерживается

Состояние и долги **переписываются**, отвергнутое **дописывается**.

Числа шапки сторожит `tests/test_ledgers_are_current.py`: номер последнего кейса
сверяется с вердиктами, счёт стенда — с реестром. Соврать в прозе можно, в
числах нет.

Чего сторож не даёт: он молчит о том, верна ли проза. «Следующий шаг» может
устареть, строка в «Отвергнутом» может не появиться. Это на добросовестности
того, кто пишет.
