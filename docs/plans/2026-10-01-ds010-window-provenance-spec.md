# Спецификация DS-010: происхождение прогнозов в измерении по окнам

**1 октября 2026.** Предъявлена владельцу и согласована в тот же день: решения
1 и 2 — «да», 3 — «не переводить». Задача — [backlog](../backlog.md), DS-010; дефект — класс 19
[журнала повторов](../recurrence-ledger.md).

## Дефект, который закрывается

В кейсах 3–5 одна модель, обученная на обучающей части **последнего** окна,
давала прогнозы для **всех** окон. Обучающая часть последнего окна содержит
строки, чей исход стал известен до его начала, — среди них оценочные строки
ранних окон. N7 мерил устойчивость знака в ранних окнах на строках обучения и
объявил её устойчивой. Сколько строк пересеклось, не посчитано: данных кейсов в
облачной сессии нет.

N7 не возразил по двум причинам, обе проверены по коду:

| Причина | Где |
|---|---|
| прогнозы окна — голый `pl.Series`; связи с обучением конкретной модели нет | `measure.py`, `stability_across_windows` |
| обучающая часть окна — публичное поле `Part.train`; построитель читает её мимо журнала, а `samples.fit(...)` — только объявление | `split.py`, `Part`; построители кейсов, `examples/synthetic-delay/run.py:126` |

Состав окна в журнале — обучение и оценка **вместе** (`split.extent_of`). Для
итогового измерения это верно: независимость резерва проверяется против
всего, чего касались. Для N7 этого мало: нужно знать, какие строки модель
видела, отдельно от строк, на которых её оценивают.

## Что проверяется

Проверяется **состав и время**, а не число моделей. Для каждого окна `w` и
записи обучения `F`, по которой получены его прогнозы:

1. **Строки не пересекаются:** единицы решения обучения `F` не пересекаются с
   единицами решения оценочной части `w`. Единица решения — значение колонки с
   ролью `ENTITY_ID`, как в `Extent` сейчас.
2. **Метки не из будущего:** момент, к которому были известны все метки
   обучения `F`, строго раньше начала `w`:
   `max(__label_known_at по размеченным строкам F) < w.start`. Строгое
   неравенство — то же, каким `split_by_windows` отбирает обучение окна
   (`KNOWN_AT < window.start`). Сравниваются моменты, а не показания часов:
   время с поясом — в UTC, как в polars (дополнено после ревью `da79e10`: в час
   перевода часов местное сравнение принимало будущие метки), целыми
   микросекундами без промежуточной даты (ревью `69074aa`: края календаря).
   Момент знания меток хранится числом из `dt.epoch("us")` polars, а не датой
   Python: база правил поясов Python может расходиться с polars (ревью
   `bae53e9`). Начало окна переводится в число тем же литералом polars, что и
   в отборе `KNOWN_AT < start` (ревью `db1214b`: утверждение, что polars
   переводит его по `utcoffset()` Python, было неверно для именованных
   поясов). Наивное и поясное время несопоставимы — отказ, как и в polars.
   Оговорка о точности (ревью `a0ba81b`): у колонки `KNOWN_AT` в миллисекундах
   polars округляет начало окна до её точности, а проверка сравнивает
   микросекунды; метка, известная менее чем за миллисекунду до начала окна,
   может быть принята проверкой, хотя сплит её в обучение окна не включил.
   Будущих меток это не пропускает.

Следствия, которые требует критерий DS-010:

| Случай | Итог |
|---|---|
| своя модель на каждое окно, обученная на обучающей части этого окна | проходит |
| одна модель, обученная на обучающей части **самого раннего** окна, для всех окон | проходит: её метки известны до начала каждого окна, строки — до начала самого раннего |
| одна модель на обучающей части **последнего** окна для всех окон (кейсы 3–5) | отказ по ранним окнам: пересечение строк и метки после начала окна |
| обучение на метках, известных после начала окна, **без** пересечения строк | отказ по условию 2 |
| прогнозы без записи обучения | отказ |

## Контракт

### Журнал выборок (`samples.py`)

* **Окно регистрируется с тремя составами.** Общий (обучение и оценка вместе)
  остаётся, как сейчас, и по-прежнему служит независимости итогового
  измерения. Добавляются состав оценочной части и начало окна. Новый метод
  `register_window(window, extent, evaluation, frame, training)`;
  `register` для резерва не меняется.
* **Обучающая часть окна принадлежит журналу**, как резерв сейчас. Её отдаёт
  единственный вызов `training(window, decision) -> Fit`. Он записывает
  обращение `FITTING` и тем же действием выдаёт запись обучения `Fit`:
  - кадр обучающей части — только строки с меткой;
  - единицы решения этих строк;
  - момент, к которому известны все их метки;
  - имя окна, из которого она взята.
* **Пустая обучающая часть** — отказ при выдаче: учить нечему, и момент
  «известны все метки» не определён.
* **Журнал помнит выданные записи.** Запись, которую журнал не выдавал
  (построенная вручную или взятая из другого журнала), отвергается.
  Сверяется ровно тип `Fit` и тождество с выданной записью — по утверждённой
  границе входов.

### Сплит и прогон (`split.py`, `runner.py`)

* `runner.run` после регистрации в журнале снимает `Part.train` с результата,
  так же как `SplitResult.reserved` сейчас. `split_by_windows` сам по себе
  обучающую часть по-прежнему возвращает: снимает её только прогон.
* **Всё, что читает обучающую часть, считается до передачи журналу:**
  - проверки (`split_checks`, перекрытие окон признаков, purge) — порядок в
    `runner.run` уже такой;
  - число строк обучения для `Result.summary()`;
  - `objects_across_splits(result)` — его зовут построители закрытых кейсов
    после прогона. Результат вычисляется в прогоне и хранится в `Result`,
    вызов остаётся прежним.
* Момент «известны все метки» берётся из колонки `__label_known_at`, которую
  `split_by_windows` уже ставит на каждую строку. Новых вычислений над
  данными нет.

### Измерение по окнам (`measure.py`)

* `stability_across_windows(samples, predictions, rule, decision)`.
  `predictions` — словарь «окно → `Prediction(fit, scores)`» вместо
  «окно → `pl.Series`». **Это изменение публичного контракта.**
* Отказ — `ValueError` с именем окна и причиной до расходования окна, если:
  - у окна нет записи обучения;
  - запись чужая;
  - строки пересекаются (с числом общих единиц);
  - метки из будущего (с датами: момент знания меток и начало окна).
* **Входы всех окон проверяются до расходования первого** (дополнено после
  ревью `648a185` и `ab5d402`): окна читаются как аудит, проверяются
  происхождение, длина, значения, оценки правила и допустимость выбора (P7),
  затем окна расходуются как выборки выбора. Данные обучающей части
  проверяются при регистрации окна.
* **Отчёт N7 называет происхождение** каждого окна: из какого окна взята
  обучающая часть, сколько в ней строк и до какой даты известны её метки.

## Чего DS-010 не делает — названные пределы

* **Построитель, обошедший штатный путь, не обнаруживается.** Можно получить
  `Fit` и обучить модель на другом кадре: пересобрать сплит самому или прочесть
  данные из источника. Можно приложить к прогнозам чужой `Fit`. Ядро видит
  запись, а не саму модель. Это предел, названный в критерии DS-010 и в
  классе 19.
* **Итоговое измерение на резерве не меняется.** Резерв отделяется до
  построения окон, и класс 19 его не задевает.
* **Закрытые кейсы 3–5 не пересчитываются.** Дополнения к вердиктам уже
  дописаны, число пересёкшихся строк остаётся открытым долгом.

## Приёмка

Тесты на синтетическом мире стенда:

* все пять случаев таблицы «Что проверяется» — проходит или отказ, и отказ
  называет окно и причину с числами;
* запись, построенная вручную, и запись из другого журнала — отказ;
  подкласс `Fit` или `Prediction` — отказ;
* пустая обучающая часть — отказ при выдаче;
* `Part.train` после регистрации недоступен (при решении 1 «да»);
* отчёт N7 на честном случае совпадает с прежним, кроме новых строк
  происхождения;
* `examples/synthetic-delay` проходит на новом пути, его отчёт измерения
  прежний;
* пороги проверок не меняются;
* `tools/check.py` проходит;
* независимое ревью Codex принимает.
