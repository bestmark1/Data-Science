# Карта техник: что из современной практики DS покрыто проектом

30 сентября 2026. Составлена по просьбе владельца «ничего не забыть и не упустить»
после вопроса про uplift, разбиение train/validation/test, кросс-валидацию и
дисбаланс классов. Инвентаризация — по коду `src/dsx`, построителям кейсов и
`pyproject.toml` на `a8cfa28`.

## Рамка, в которой читать карту

Решения владельца 29–30 сентября (вопросы 1–4 раунда про техники):

1. **Инструмент ловит ошибки применения техник, а не реализует их.** Технику
   ядро реализует только там, где проверке нужен эталон для сравнения. Строить
   модели — дело построителя проекта.
2. **Пересэмплирование по умолчанию не применяется.** Если объявлено — только
   внутри обучающей части и с перекалибровкой на отдельном окне. Измерение
   дополняется PR-AUC относительно доли класса и порогом по стоимости ошибок.
3. **Uplift откладывается до рабочей задачи**, требования записываются в
   backlog (DS-009).
4. **Порядок:** довести PR #2 → малый PR (PR-AUC и порог по стоимости в
   `measure.py`, правило о пересэмплировании в `AGENTS.md`) → кейс 21.

Два ограничения проекта отсекают часть «стандартных» практик намеренно:

* **в кейсах нет подбора гиперпараметров** — настройки фиксируются до прогона,
  иначе резерв расходуется на выбор; в рабочем проекте подбор разрешён, но
  только вложенный и по времени;
* **нет случайной кросс-валидации** — единица разбиения — окно по времени
  известности метки; случайный K-fold на данных со временем даёт завышенную
  оценку, и штатный путь `split_by_windows` его не допускает.

Статусы: **есть** — реализовано и проверено стендом или тестами; **частично** —
покрыта часть риска, остаток назван; **нет** — пробел, предложен в backlog;
**вне области** — не нужно, пока нет задачи этого типа; **отвергнуто** —
рассмотрено и отклонено, см. «Отвергнутое» в handoff.

## 11. Причинный вывод и uplift

Решение 3: откладывается до рабочей задачи. Требования, которые должны войти в
DS-009, чтобы не собирать их заново:

* **данные:** рандомизированный эксперимент или известная вероятность
  назначения; флаг воздействия — объявленная роль в формуляре; `TargetKind.UPLIFT`
  уже есть в перечне, но не входит в `SUPPORTED`;
* **проверки до модели:** перекрытие распределений групп (propensity overlap —
  та же идея, что `ComparableSupport`); доля групп совпадает с объявленной
  (sample ratio mismatch); признаки после воздействия запрещены
  (`FeatureAfterDecision` переносится);
* **модели:** мета-обучатели S/T/X, doubly robust (DR-learner), causal forest;
  библиотеки scikit-uplift, CausalML, EconML — новые зависимости, по
  согласованию;
* **измерение:** Qini и AUUC с интервалом bootstrap, сравнение с назначением
  всем и никому; разбиение по-прежнему по времени;
* **стенд:** инжекторы с известным эффектом и с эффектом, подменённым отбором.

A/B-тесты, CUPED, последовательные тесты — вне области, пока инструмент не
анализирует эксперименты; SRM входит в uplift как проверка данных.

## 14. Передний край: прорывное, а не только распространённое

Добавлено по замечанию владельца: одни распространённые техники дают «средний
по больнице» ответ. Источники проверены 30 сентября 2026 поиском. Полные тексты
arXiv из облачной сессии недоступны (сеть закрыта), поэтому выводы ниже сделаны
по аннотациям и сводкам. Перед тем как на них опираться, прочитать статью.

### Главная находка: лидер бенчмарка — не лидер на наших данных

На TabArena (живой бенчмарк, 51 набор) четыре лучшие одиночные модели —
табличные foundation-модели (TabPFN-3, TabPFN-2.6, RealTabPFN-2.5, TabICLv2).
Лучший бустинг отстаёт примерно на 240 Elo. Но TabArena разбивает данные
случайно. BeyondArena (июнь 2026, 142 набора) разбивает по времени и по группам.
На таких разбиениях foundation-модели **уступают** бустингу и RealMLP. Отдельная
работа (июль 2026) показала: все эти модели систематически теряют качество при
сдвиге распределения, а преимущество моделей, предобученных на реальных данных,
объясняется лучшей подгонкой внутри распределения.

Все двадцать кейсов проекта размечены по времени. Прорывной метод, принятый по
чужому лидерборду, повторил бы ту же ошибку, которую проект ловит у других:
результат, полученный на случайном разбиении, выдаётся за результат по времени.
Отсюда предложение: **прорывной метод входит претендентом**. Он измеряется
против действующего на нашем разбиении по времени и по тому же правилу шумового
пола, что и опорный результат аналогов. Решение ещё не принято, это вопрос
владельцу.

### Для построителя модели: претенденты

| Метод | Что даёт | Оговорка |
|---|---|---|
| TabPFN-2.5 … 3.5, RealTabPFN | без настройки лучший результат на малых данных (до ~50 тыс. строк) при случайном разбиении | лицензия TabPFN-2.5 запрещает коммерческое и внутреннее деловое применение, включая результаты; для рабочего проекта у работодателя нужна коммерческая лицензия. Условия 3.x не проверены |
| TabICLv2 (ICML 2026) | открытая модель того же класса | лицензию проверить |
| Drift-Resilient TabPFN | обучение в контексте с учётом сдвига во времени | исследовательская работа, зрелость не проверена |
| RealMLP, TabM | нейросети, на временных и групповых разбиениях держатся наравне с настроенным бустингом | нужен подбор, то есть только рабочий проект |
| Признаки, предложенные LLM (CAAFE и подобные) | идеи признаков из описания задачи | главный риск — утечка; каждый такой признак проходит проверки доступности как любой другой |

### Для ядра: что усиливает проверки

| Метод | Что даёт проекту | Связь |
|---|---|---|
| Оценка качества без меток (CBPE, PAPE, NeurIPS 2025) | метрику последних окон можно оценить до созревания меток; расхождение оценки с фактом после созревания — сигнал смены связи, а не только сдвига признаков | отложенная метка — основной тип задач проекта; требует калибровки, то есть связан с кандидатом Г |
| Prediction-powered inference (PPI++) | честные интервалы при малом числе созревших меток и большом числе оценок | `MeasuredPartsAreUsable`, bootstrap в `measure.py` |
| Conformal risk control | порог с гарантией на долю пропусков или ложных тревог, а не точечная оценка | расширение порога по стоимости (решение 2) |
| Взвешенный и адаптивный conformal (covariate shift, ACI) | покрытие, которое сохраняется при сдвиге во времени | окна по времени |
| Мультикалибровка | калибровка сразу по всем пересечениям подгрупп, а не по одному признаку за раз | обобщает `segment_bias` (N10) и кандидата Д |
| Мир стенда из случайной структурной причинной модели, как в априорном распределении TabPFN | тысячи миров разной формы вместо нескольких ручных; частота срабатывания вместо исхода на одном seed | прямо отвечает на класс 18 журнала повторов и DS-006 |
| Anytime-valid вывод (e-values) | повторный взгляд на накапливающиеся данные без роста ошибки | мониторинг и учёт правила остановки |

### Для uplift (DS-009)

* **Причинные foundation-модели** (CausalPFN, работы ICLR 2026 и сентября 2026)
  по аннотациям обходят S/T/X-learner, TARNet и CFRNet в оценке индивидуального
  эффекта. Это претенденты с теми же оговорками про разбиение по времени.
* **Наилучший оценщик эффекта не обязательно даёт наилучшее решение.**
  Двухшаговые оценщики вроде DR-learner бывают неоптимальны для выбора, кого
  воздействовать (2025). Измерять надо политику назначения (Qini, прибыль при
  бюджете), а не только точность эффекта.
* **Метрики uplift нестабильны при структурных смещениях** в данных
  рандомизированных экспериментов (KDD 2026). Нужна проверка устойчивости
  метрики, а не одно число.
