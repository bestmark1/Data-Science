30 сентября 2026. Составлена по просьбе владельца «ничего не забыть и не упустить»
после вопроса про uplift, разбиение train/validation/test, кросс-валидацию и

`pyproject.toml`.

**Вторая редакция** — после независимого ревью `f35bae1` (не принято, 14

## Рамка, в которой читать карту

Решения владельца 30 сентября (вопросы 1–4 раунда про техники):

1. **Инструмент ловит ошибки применения техник, а не реализует их.** Технику
   ядро реализует только там, где проверке нужен эталон для сравнения. Строить
   модели — дело построителя проекта.
2. **Пересэмплирование по умолчанию не применяется.** Если объявлено — только
   внутри обучающей части и с перекалибровкой на отдельном окне. Измерение
   дополняется PR-AUC относительно доли класса и порогом по стоимости ошибок.
3. **Uplift откладывается до рабочей задачи**, требования записываются в
   backlog (DS-009).
4. **Порядок:** довести PR #2 → DS-008 (PR-AUC и порог по стоимости в
   `measure.py`, правило о пересэмплировании в `AGENTS.md`) → кейс 21.

Два ограничения проекта отсекают часть «стандартных» практик намеренно:

* **в кейсах нет подбора гиперпараметров** — настройки фиксируются до прогона;
  в рабочем проекте подбор разрешён, но только вложенный и по времени;
* **случайного K-fold нет в штатном API** — `split_by_windows` строит части
  только по времени. Произвольный код построителя этим API механически не
  ограничен.

### Статусы

Статус описывает одно: что есть и какой ценой это держится.

* **код** — реализовано в ядре, указано где; ограничения названы в той же
  строке;
* **диагностика** — код сигнализирует о проблеме, но не устраняет её и не
  строит правильный вариант;
* **правило** — записано в `AGENTS.md` или протоколе, автоматически не
  проверяется;
* **нет** — отсутствует; если есть предложение, указан кандидат из «Итога»;
* **вне области** — не нужно, пока нет задачи этого типа.

Приёмка отдельно: всё помеченное «код» проверено тестами и стендом, если не
сказано иначе. DS-004 (аналоги) — на независимой проверке, статус `review`.

## 3. Разбиение и валидация

Три разные вещи, которые первая редакция смешивала: **построение частей** (ядро),
**измерение готовых прогнозов** (ядро) и **переобучение модели по окнам**
(построитель).

| Техника | Статус | Где и граница |
|---|---|---|
| Части train / evaluate по времени и резерв | код | `split_by_windows`: expanding train, в него допускаются только метки, известные до начала окна; отдельного объекта validation нет |
| Сравнение с правилом по окнам | код | `stability_across_windows` (N7) меряет ГОТОВЫЕ прогнозы по окнам и сам не переобучает. Это не rolling CV |
| Переобучение отдельной модели на каждом окне | нет в построителях | в `subscription-churn` и `nys-wc-claims` одна модель, обученная на train последней части, оценивается во всех окнах; оценочные строки ранних окон входили в её обучение. Долг записан в handoff |
| Purge перекрытия окон признаков | код | `purge_overlapping_train`, `FeatureWindowOverlap`: для объявленных окон и повторных объектов |
| Незрелые метки в оценочных частях и резерве | диагностика | `LabelImmaturity` (A12) сигнализирует о доле незрелых; зазора не создаёт. Отдельного embargo нет |

## 11. Причинный вывод и uplift

Решение 3: откладывается до рабочей задачи. Требования для DS-009:

* **идентификация:** рандомизированный эксперимент или, для наблюдательных
  данных, явно названные предпосылки — отсутствие скрытых смешивающих,
  перекрытие групп (overlap), отсутствие взаимного влияния единиц
  (interference); флаг воздействия — объявленная роль в формуляре;
  `TargetKind.UPLIFT` есть в перечне, но не в `SUPPORTED`;
* **проверки до модели:** перекрытие распределений групп; доля групп совпадает
  с объявленной (sample ratio mismatch); признаки после воздействия запрещены;
* **модели:** мета-обучатели S/T/X, DR-learner, causal forest; причинные
  foundation-модели — претенденты (раздел 14); библиотеки — по согласованию;
* **измерение:** точность эффекта и полезность политики — разные цели;
  мерить политику назначения (Qini, прибыль при бюджете) с интервалом;
  проверять устойчивость метрики; разбиение по времени;
* **стенд:** миры с известным эффектом и с эффектом, подменённым отбором.

## 14. Передний край

Добавлено по замечанию владельца: одни распространённые техники дают «средний
по больнице» ответ. Первая редакция опиралась на аннотации, и ревью нашло
утверждения сильнее источников. Ниже — только то, что подтверждено полными
текстами в ревью, с условиями.

### Foundation-модели: чужой лидерборд не заменяет наше сравнение

* На TabArena, где разбиение случайное, верх одиночных моделей в последнем
  снимке заняли foundation-модели. Числа места и отрыва не закреплены
  снимком — не цитировать как текущие.
* BeyondArena (июнь 2026) на агрегате временных и групповых разбиений даёт
  преимущество настроенному бустингу и RealMLP. Это результат для конкретных
  версий и конфигураций, а не закон для всех временных задач.
* Отчёт TabPFN-3.5 (сентябрь 2026): на полном временном и групповом наборе
  лучшие настроенные ансамбли MLP сохраняют преимущество, на подмножестве до
  100 тысяч строк TabPFN-3.5 сопоставим с лучшими. Протокол групповой оценки
  отличается от BeyondArena.
* OOD-работа (июль 2026, девять моделей, три набора): модели теряют качество
  при сдвиге; объяснение через лучшую подгонку внутри распределения авторы
  дают как предположение.

Обоснованный вывод один: **выбирать модель по чужому лидерборду нельзя, нужно
сравнение на нашем разбиении по времени.** Отсюда кандидат И.

**Лицензии.** Бесплатная лицензия TabPFN-2.5 (v1.1) разрешает определённое
внутреннее тестирование и сравнение; для применения результатов в бизнес-
процессах, эксплуатации и коммерческих решениях нужна отдельная лицензия.
Проверять надо условия на код, веса и выходы по отдельности и способ доступа;
открытый код сам по себе недостаточен. Условия TabICLv2 и TabPFN-3.x не
проверены.

### Для ядра: методы и их условия

| Метод | Вид гарантии | Требования | Годится ли проекту |
|---|---|---|---|
| CBPE | оценка метрики без меток | калиброванная модель; связь признаков с исходом не меняется | до меток смену связи не видит; после созревания сравнение с фактом — аудит предпосылок, не диагноз смены связи (мешают ошибки калибровки, отбор созревших меток, шум) |
| PAPE | то же с поправкой калибровки на сдвиг ковариат | условия переноса, общий носитель распределений, пригодная оценка отношения плотностей; смена связи исключена | исследование применимости |
| PPI++ | интервал по малому числу меток и большому числу прогнозов, асимптотический | размеченные и неразмеченные — из одной популяции | **в постановке «старые метки → свежие окна» не обоснован.** Пример ревью: старая доля 0.1, новая 0.8, модель везде даёт 0.1; оценка 0.1 при истинном 0.8, и объём этого не лечит |
| Conformal risk control | контроль ожидаемого ограниченного монотонного риска | обменяемость, монотонность риска | стоимость ошибок по порогу в общем случае немонотонна: готовой гарантии для DS-008 нет |
| Взвешенный conformal, ACI | покрытие при сдвиге; для ACI — частота ошибок во времени | условия переноса; для ACI задержанная обратная связь названа авторами открытой задачей | исследование |
| Мультикалибровка | калибровка по заданному семейству подгрупп | семейство задаётся заранее; прогнозы меняются | обобщение N10, кандидат Д2 |
| Anytime-valid вывод | повторные взгляды без роста ошибки | нужна последовательная конструкция (e-process); произвольные e-values правила остановки не отменяют | мониторинг; источник первичный не читан |
| Стенд из случайных структурных причинных моделей | разнообразие миров | генератор и его априорное распределение со своими ограничениями | кандидат Ж; DS-006 не закрывает — меняет семейство миров |

### Для uplift (DS-009)

* Причинные foundation-модели выигрывают не везде: в работе сентября 2026 на
  RealCause-Lalonde средний ранг PEHE у T-learner 1.40 против 1.75 у CausalPFN
  (меньше лучше); в CausalFM на ACIC2016 PEHE у X-learner 0.519 против 0.638.
  Претенденты, не замена.
* Точность оценки эффекта и полезность политики назначения — разные цели;
  DR-learner бывает неоптимален для решения (2025).
* Метрики uplift нестабильны при структурных смещениях — нерандомизированном
  отборе, скрытом смешении (KDD 2026, полусинтетический бенчмарк).

**Правило претендента в редакции после ревью.** Заранее фиксируются претендент,
метрика и разбиение. Считается интервал bootstrap **разницы метрик на
одинаковых строках**, как в `measure_contrast`. Преимущество засчитывается,
если нижняя граница разницы выше заранее объявленного минимального полезного
улучшения, не ниже нуля; для функций потерь направление обратное. Единица
bootstrap — по структуре зависимости. Несколько претендентов по итоговому
резерву не отбираются.
