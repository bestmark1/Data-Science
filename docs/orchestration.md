# Режимы работы

Вынесено из `AGENTS.md`: нужно только в режиме оркестратора. Общие правила
проекта — в [AGENTS.md](../AGENTS.md).

**Desktop и оркестратор используются по очереди.** Общие ограничения,
исследовательские решения и критерии готовности действуют в обоих режимах.
Текущий режим записывает координатор в [handoff](handoff.md).

## Desktop

Существующий порядок работы через Codex/Claude и жёсткие назначения моделей
из инструкций соответствующего клиента сохраняются. Таблица ниже относится
только к оркестратору и не заменяет назначения desktop-режима.

## Оркестратор — Herdr

Архитектор/координатор совмещает архитектурную и координационную роль:
читает состояние проекта, принимает архитектурные решения в согласованных
границах, определяет приоритеты, декомпозирует работу и выдаёт задачи,
организует независимую проверку, принимает результаты по утверждённым
критериям и поддерживает handoff. Отдельная иерархия для этих обязанностей
не создаётся.

Назначения владельца; используются **существующие открытые панели Herdr**.
Создавать или повторно запускать панели для назначения задачи не нужно.

| Роль | Модель | Reasoning | Среда и ответственность |
|---|---|---|---|
| Архитектор / координатор | Codex GPT-6 Astra (`gpt-6-astra`) | high | Существующая панель Codex в Herdr; архитектура, декомпозиция, приоритеты, постановка задач, приёмка и состояние проекта |
| Senior-разработчик | Claude Opus 5 | high | Существующая панель Claude в Herdr; сложная реализация, отладка и техническое ревью чужих изменений |
| Frontend и тестирование | Codex GPT-6 Astra | high | Существующая панель через **pi** в Herdr; интерфейс, тесты и независимая проверка пользовательского сценария, в том числе без frontend |
| Middle-разработчик | Muse Spark 1.3 Contributor — Free | high | Существующая панель через **pi** в Herdr; ограниченная спецификация, механические изменения, небольшие исправления |
| DevOps | DeepSeek v4 Flash | high | Существующая панель через **pi** в Herdr; окружение, сборка, инфраструктура, подготовка деплоя и выявление ненужных файлов/зависимостей |

Названия моделей в таблице переданы владельцем. Технические ID моделей,
провайдеров и применённый reasoning проверяются в доступной конфигурации
соответствующей панели; по отображаемому названию их не угадывают. Общий
default клиента не подтверждает настройку уже открытой панели. Расхождение
сообщают владельцу, настройки молча не меняют. Запуск через pi — часть
назначения трёх указанных ролей, а не дополнительная роль.

Задание выдаётся по необходимости, с конкретным результатом и границами
файлов; задействовать все панели в каждой задаче не требуется. Исполнитель
сохраняет чужие изменения и сообщает фактическое состояние. Он не объявляет
свою работу независимо принятой: другого проверяющего назначает координатор.
Роль DevOps сама по себе не разрешает deploy, удаление данных, окружения или
несвязную уборку; такие действия отдельно согласуются с владельцем.

## Backlog и передача между режимами

Единая очередь — [backlog.md](backlog.md). За актуальность отвечает
архитектор/координатор: обновляет её при выдаче задачи, обнаружении блокера,
передаче на review и завершении. Поля задачи: стабильный ID; задача и
ожидаемый результат; приоритет; статус (`todo`, `in_progress`, `blocked`,
`review`, `done`); назначенная роль; зависимости/блокер; критерий приёмки;
ссылка на спецификацию, решение или проверку. `done` ставится после
предусмотренной приёмки. Исследовательское ограничение само по себе не
становится задачей на исправление.

При смене режима следующий агент читает общие инструкции и handoff,
проверяет HEAD, `git status` и diff и продолжает с зафиксированного шага.
В handoff обязательны текущий режим, завершённый этап и следующий шаг,
незакоммиченные изменения с назначением, выполненные проверки и непроверенное,
решения владельца. Backlog в handoff целиком не копируется. История дефектов
и защит остаётся в журнале повторов, устойчивые правила — в `AGENTS.md`.

Что переключение режима не разрешает (commit, push, изменение архитектуры,
запуск исследования) — в [AGENTS.md](../AGENTS.md#режимы-работы). Механизм
одновременной работы двух сред не вводится.
