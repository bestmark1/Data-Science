# Доступ к существующим панелям Herdr

Проверено 11 сентября 2026. Сервер и клиент 0.9.0, совместимы,
`restart_needed: no`. Сокет: `/Users/bestmark1/.config/herdr/herdr.sock`.
Панели проекта: workspace `w2`, tab `w2:t1`.

Первоначальный вывод об отсутствии доступа по пустому `HERDR_ENV` был
слишком сильным: инструмент запуска команд не унаследовал `HERDR_*`,
а запросы к сокету внутри sandbox получали `Operation not permitted`.
После прямого поручения владельца подтвердить доступ выполнены проверки
вне sandbox. `herdr agent read w2:p7` показал текущую переписку координатора;
`agent list`, чтение других панелей и доставка задач работают.
Ни одна панель не закрыта, не создана и не перезапущена.

| Роль | Панель / существующее имя агента | Подтверждённая модель | Reasoning | Основание |
|---|---|---|---|---|
| Архитектор / координатор | w2:p7 / codex | gpt-6-astra, Codex | xhigh | Последний turn_context текущей сессии 01a08ab3-f448-71e3-871a-1921179bc258 |
| Senior | w2:p1 / Claude | Opus 5, выбранный alias opus | high | Экран Claude: Set model to Opus 5, Set effort level to high; точный backend ID после переключения ещё не наблюдался |
| Frontend / тестирование | w2:p9 / pi-codex-b | openai-codex / gpt-6-astra, через pi | high | События model_change и thinking_level_change текущей pi-сессии; исполненный DS-001-U |
| Middle | w2:pA / pi-grok | opencode / muse-spark-1.3-contributor-free, через pi | high | События сессии, точный выбор /model и /thinking high; DS-001-F доставлено |
| DevOps | w2:pB / pi-oc-b | opencode / deepseek-v4-flash, через pi | high | События model_change и thinking_level_change; экран и полученное задание на alias |

Имена `pi-grok` и `pi-oc-b` — старые метки агентов, не модели. Их не
переименовывали. В middle-панели был открыт selector на обычном Muse Spark
1.3, но активной моделью по истории уже была Contributor Free. Точная модель
повторно выбрана явно, reasoning high подтверждён; общий default pi не менялся.
Старые ответы Claude до переключения имели model `claude-sonnet-5`;
это не доказательство текущей модели, выбранной после них через /model.

Для продолжения проверять актуальный `herdr agent list`, использовать
явные pane ID или полученные live names. На данной машине запросы к сокету
требуют разрешённого выхода из sandbox. Отсутствующие переменные не
подставлять искусственно. Живые статусы Herdr сверять с экраном: сразу после
prompt CLI может ещё вернуть старое `idle`.

Независимому проверяющему передано задание без отчётов реализации и приёмки;
middle владеет только `tests/test_applied_example.py`; координатор ведёт docs.
DevOps получил отдельную пользовательскую задачу на zsh-alias вне репозитория.

## Уточнение владельца: архитектор с reasoning high

Позднее 11 сентября владелец сменил назначение архитектора/координатора на
`gpt-6-astra`, reasoning `high`. Таблица выше сохраняет первоначальный снимок,
актуальное назначение находится в `CLAUDE.md`.

В существующей панели `w2:p7` через `/model` выбрана прежняя `gpt-6-astra`,
затем `High` вместо `Extra high`. Клиент сохранил
`model = "gpt-6-astra"` и `model_reasoning_effort = "high"` в своей конфигурации.
Панель не перезапускалась. Последний `turn_context` относится к уже начатому
запросу с `xhigh`; фактический новый запрос с `high` ещё предстоит подтвердить.
Другие панели и файлы назначений desktop-режима не изменялись.
